# 目标详情交互原型 Design QA

验收日期：2026-11-04

产品方向：内容、状态与操作解耦

实现范围：合成数据的本地 HTML 交互原型

预览：`http://127.0.0.1:4173/`
实现代码：`prototypes/goal-panel/src/`

## 本轮验证的问题

Agent 输出通常是非结构化的。原型需要验证：不要求 Agent 填写固定字段时，用户是否仍能从目标详情恢复上下文、阅读原始交接并完成当前操作。

## 视觉与结构检查

- 单个桌面宽弹窗，顶部显示目标上下文和状态，正文是一列原始消息。
- 最新消息保留自然段和换行，没有拆成事实、选项、建议、证据等业务卡片。
- 附件独立列出，历史消息默认折叠。
- 底部操作区固定在弹窗内，根据状态切换，不解析正文。
- 深色和浅色主题保持相同层级、边界和操作优先级。
- 外层的注意力、全部目标、概况与详情弹窗共用同一份合成目标数据。

## 交互覆盖

1. 从注意力条目打开“等你回复”目标，可以在自由文本框输入并看到交回管家的回执。
2. 从全部目标切换到同一个详情组件，证明两个入口没有两套布局。
3. “等你验收”只提供验收通过、退回修改和问管家；退回后出现自由文本建议，不再显示结构化原因。
4. “等待外部”首屏明确说明现在不用处理，同时保留“有进展，告诉管家”的次级入口。
5. “需要你排障”将打开 Herdr 工作现场作为主操作，并保留告诉管家的次级入口。
6. 附件可打开并出现反馈；“你 ↔ 管家”的此前消息可展开/收起，并且只属于当前目标。
7. 阅读详情不会自动移出注意力；只有验收或交接事件改变当前原型内的状态。
8. 验收通过后目标离开注意力，并在列表计数中减少。
9. 深色/浅色切换后，弹窗文字、状态和按钮仍可读。
10. 构建与 Sites worker 测试通过；重新加载后的页面没有新增控制台错误。开发热更新曾报告旧文件 `ModalPrototype.jsx` 和 `modal-prototype.css` 已被删除，这属于旧引用清理过程中的历史消息，当前入口已改为 `App.jsx` 和 `styles.css`。

## 发现与修正

### 1. 旧的 A/B/C 方案把内容预结构化

早期草案把决定正文拆成问题、事实、选项、建议和证据，并让布局假设 Agent 每次都能稳定输出这些字段。这与真实 Agent 输出不符，已删除方案切换和全部结构化卡片。

### 2. 操作曾跟正文写法绑定

早期原型会根据正文内容展示“批准这个决定”等按钮，容易把普通回复或方案讨论误当作授权。现在操作只由状态驱动；回复本身不改变状态，验收和退回是独立命令。

### 3. 等待事项曾塞入无效主按钮

等待外部事项不需要人反复处理。现在以“现在不用处理”为主信息，只保留低优先级的上报入口。

### 4. 弹窗信息密度过高

历史消息和附件曾被重复塞进正文卡片。现在最新消息占据主阅读面，历史默认折叠，附件使用轻量资源行，操作固定在底部。

## 剩余边界

- 原型只使用内存中的合成数据，不能证明消息同步、状态写入、附件清理和失败重试已经接通。
- 附件点击、打开现场和回复发送使用原型反馈，不调用真实 Crewvane CLI 或 Herdr。
- 未做 VoiceOver 和完整屏幕阅读器人工测试；已保留语义标题、状态文本、焦点环和键盘可操作按钮。
- 状态更新是后续生产实现的前提。若 Agent 只能在正文里说“已完成”而不写状态事件，目标不会自行退出注意力。

## 结论

当前方案通过本轮原型验收。它把不可控的内容完整保留，把稳定的产品控制面缩小为状态和少量明确命令，满足“内容非结构化时仍能快速理解和处理”的核心问题。
