# Crewvane 0.4 验收记录

状态：核心真实闭环已通过；最终安装包仍需重新验收。

## 已验证

- 类型检查；CLI 3 项、core 17 项、desktop / Herdr adapter 5 项单元测试通过；桌面生产构建通过。
- 打包应用桌面回归：深浅主题、侧边栏收起、手动与管家目标、等待、验收、退回、工序编辑与设置；没有 renderer 错误。
- 打包应用内终端：隔离命名 Session 中真实启动 Herdr TUI，发送 shell 命令并读到实际输出；隐藏与重新打开后复用同一 utility process；深度主题、展开和跨工作区输入拒绝通过。
- 终端不再在后台连接时自动显示；新建目标表单保持打开，草稿与输入焦点不会被终端事件抢走。
- Agent 启动命令可包含模型等原生参数；负责人和工人留空按层级跟随。命令不经过 shell，拒绝管道、重定向和变量展开。
- 自然语言真实试用：一位管家接收一条自然语言请求并创建三个目标；实际启动 `trial-owner`，负责人写 `alpha/result.md` 并执行文件断言，提交真实交付与 Herdr 现场。
- 同一试用自动写入等待 YR 与出行决定；到期提醒进入注意力且去重。人工退回后，负责人继续在原 Pane 修改并实跑 `READY` / `VERIFIED` 双标记检查，管家复核后重新提交；人工在桌面验收通过。
- 桌面重启后目标、已验收状态、提醒去重记录与现有管家现场保持；再次打开复用了同一个 `concierge`，没有创建第二位。
- 新建管家目标复用现有唯一 `concierge`，消息中包含目标 ID；连续目标不需要新建管家会话。

## 未完成

- 最终版本 ZIP / DMG、内置 CLI、隔离属性、严格签名与独立机器启动。
- 发布前在最终提交上重跑完整自动化、打包应用和安装包门禁。

早期试用中曾有脚本直接创建负责人、负责人没有收到实际任务的问题，不能证明该闭环。当前记录来自修正后的真实试用：唯一用户输入通过应用内终端交给管家；负责人真实工作状态、文件、命令输出和 Herdr 引用均已核对，脚本没有代建负责人或伪造检查。负责人首轮完成、人工退回、原负责人重新修改和最终验收均有时间线。
