# v0.4.2 工作台与 Herdr 验收

日期：2026-11-04。环境：macOS arm64，正式打包的 Crewvane.app。

## 修复范围

- 左上角“我的工作台”只回到全部项目与个人事项的总览，不再打开目录选择器。工作区存储位置只在首次初始化和设置中出现；选择、重复选择、取消、无效目录和切换都有可验证反馈。项目通过项目栏“添加项目”创建，目录可选。
- 启动检查官方 Herdr TUI 版本；缺失或旧版时自动下载、校验并私有安装，不要求 Homebrew。Finder 启动也查询登录 shell 的 PATH 与常见安装路径。
- 自定义交互式 CLI 不再受 Herdr kind 白名单限制，保留可执行文件与原生参数，在真实 Pane 执行。核对前台 PID 后才发送任务，退出后拒绝向原现场继续发送。
- 设置中的「打开 Herdr」独立于「准备管家」。
- 菜单栏改用与 Dock 同源的像素魔法师应用图标，18pt 与 2x 图像，保留原图颜色。
- 管家职责改为只分发、协调跟进与向人交接。简单目标、返工与检查也交给独立负责人，阻塞时不得自行接手执行；初始身份、目标通知和巡检消息均传递该边界。
- 恢复已有管家时刷新身份，复用同一进程，不重复启动。通知送达、负责人登记和真实连接分别反馈；一分钟未分配先请管家核查，登记拒绝管家及其他活动目标的现场。
- 项目关联可选，CLI 创建目标可省略 `--project`。

## 已完成验证

`pnpm test`：CLI 5、core 20、desktop 17，共 42 项通过。类型检查和工作区 fast verify 通过。分发反馈调整后重新执行了桌面与终端界面回归；最后的已有管家身份刷新补充另执行单元、打包、onboarding、安装包和真实双目标回归，不改动界面与终端连接实现。

`pnpm test:onboarding` 使用隔离 HOME、应用数据、工作区与唯一测试 Session，PATH 仅含 `/usr/bin:/bin`，没有 Homebrew 或系统 Herdr：

1. 应用从官方 manifest 自动下载 Herdr，SHA-256、实际 `--version` 与目标版本一致。本轮官方 TUI 为 0.9.5。
2. 在打包界面中选择工作区、重复选择、取消、打开旧格式失败和切换；失败保留原工作区，错误没有 Electron IPC 技术前缀。
3. 在设置保存路径含空格的自定义交互式 CLI，带含空格的模型参数；真实进程记录的 argv 与设置一致。
4. 再次准备复用同一进程；新目标 ID 真实进入该 CLI 的 stdin。
5. 独立打开 Herdr；退出、重启应用后恢复工作区，复用运行中的 CLI，已安装最新 Herdr 没有再次替换。
6. CLI 退出后，向原现场发送目标被拒绝。
7. 初始身份与后续目标通知中的「不亲自执行目标」均真实进入自定义 CLI 的 stdin，目标通知要求交给独立负责人。单元回归另覆盖已识别 Agent 的初始身份、复用管家的目标更新、退回修改和巡检协调消息。

该自定义 CLI 是实际运行的可交互测试程序，用于验证启动、输入与进程关联；不将其描述为真实模型理解或完成了任务。

职责调整通过 Agent 身份和每次消息落实，不等于第三方 CLI 的工具权限隔离。自定义 CLI fixture 验证证明消息实际送达，未将其宣称为模型绝不会越过职责边界。

`pnpm test:delegation` 使用真实本机 Codex 模型，在隔离工作区通过桌面 API 连续创建两个执行目标，不由测试预先创建负责人。管家自主创建两个负责人 Tab，负责人各自写出 JSON 成果并实际运行校验，两个目标进入 `review`。成果中的 `executorPane` 与各自登记的负责人 Pane 一致，且与管家不同；Herdr 中恰好一位管家与两位负责人。重启后刷新原管家身份，两个负责人引用和 Agent 数保持不变。模型试用只证明该真实场景，不能外推为所有第三方 CLI 和模型都必然遵守职责。

`pnpm test:desktop` 通过深浅主题、侧栏收起、目标与提醒、交付退回和验收、工序保存、偏好和渲染隔离的真实界面操作。

`pnpm test:terminal` 通过应用内真实 Herdr PTY 输入，在 shell 中写出结果文件；隐藏/恢复保持同一终端进程，表单草稿与输入保留，拒绝其他 Session 输入。

`pnpm test:installers` 对本地 v0.4.2 ZIP 与 DMG 完成 SHA-256、严格签名、隔离属性、安装后启动、内置 CLI 安装与实际创建目标。

已检查深色终端与浅色工作区弹窗的渲染截图。原生文件选择器由测试注入选择结果，验证主进程选择结果处理与界面反馈，不宣称模拟了系统选择器中的手工点击。

## 测试方法纠正

- 本次安装的 Playwright 1.64.1 中，`waitForFunction(async () => ...)` 的轮询实现先对返回的 Promise 判断 truthy，随后采纳该 Promise 的值，不会在值为 false 时继续轮询。需要等待异步 IPC 结果时，改用 `expect.poll(async () => page.evaluate(...)).toBe(...)`。
- Herdr 是重绘式 TUI，外层 PTY 的原始增量字节并非内层 shell 的连续 stdout。不能用原始流里是否存在完整 `CRLF + marker + CRLF` 来判定命令执行；本次改为核验真实文件副作用，并继续检查 xterm 可访问文本。
- 自定义 CLI 可能使用 canonical TTY 输入。实测长中文身份说明超过单行限制会被拒收，现按 Unicode 字符安全分行，每行不超过 768 UTF-8 字节；回归确保字符不丢失、参数不受改动。
