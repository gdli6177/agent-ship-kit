# 工作区兼容检查与自动恢复

状态：0.6.0 实现。

## 目标

升级应用或切换到旧目录时，不相容的 `.crewvane` 数据不能让用户卡在错误页，也不能被静默覆盖。Crewvane 先验证数据，能够安全读取的 `WorkspaceState.version = 2` 原样继续使用；无法安全读取的状态整库归档，再创建一个干净的兼容工作区。

安装器不会扫描整台电脑。应用启动时会检查上次使用且仍保存在本机的设置里的工作区；用户之后选择一个旧工作区时，也会在打开前完成同样的检查。

## 触发条件

- `state.json` 的版本不是 `2`。
- `state.json` 不是有效 JSON，或缺少必要顶层结构。
- 只有旧版 `events.jsonl`，没有 v2 快照。

文件权限、磁盘、锁冲突等环境错误不会触发自动恢复。这些错误原样返回，原目录保持不动。

## 恢复顺序

1. 在 workspace 根目录取得独立恢复锁，并重新检查状态，避免桌面与 CLI 同时恢复。
2. 在相邻临时目录中完整生成新的 v2 快照、恢复事件、序号和决定账本。
3. 把原 `.crewvane` 原子重命名为 `.crewvane.backup-<时间>-<随机值>`。
4. 把准备好的新目录原子重命名到 `.crewvane`；失败时尝试把原目录恢复原位。
5. 新快照写入 `recovery` 标记，界面持续显示原因、备份路径、“打开备份”和关闭提示入口。

关闭提示只删除 `recovery` 标记，不删除备份。当前工作区已经是有效 v2 时，不做迁移，也不创建额外备份。

## 数据边界

自动恢复保留旧目录中的全部文件，但不会把 v1 任务、运行时、授权、终端引用或审批状态猜测转换成 v2 目标。旧执行现场无法可靠对应新的目标、Herdr Session 或负责人，因此只作为归档记录保留。目标原文如需重新使用，应由用户从备份中确认后再重新提交。

## 验收

1. v1 或未来版本状态会归档，当前工作区自动进入 v2，并显示原版本与备份路径。
2. 损坏 JSON、缺字段快照和仅含旧事件日志的目录同样可恢复。
3. 第二次读取不重复归档；关闭提示后备份仍在。
4. 有效 v2 状态不会触发归档。
5. 打开备份只接受当前工作区根目录下由 Crewvane 创建的 `.crewvane.backup-*` 路径。
