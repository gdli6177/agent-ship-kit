# 飞书产品描述与当前实现对照

对照来源：用户提供的《Agent ship kit》飞书文档截图（2026-11-03）。
这里核对本分支实际代码；桌面已接通、手工 CLI 可用和未来规划分别说明。

| 文档要求 | 当前覆盖 | 证据与缺口 |
| --- | --- | --- |
| 人只与船长沟通，A/B 需求可交替推进 | 部分 | 多需求可独立排队、并行，统一收件箱和船长对话已存在；新需求目前通过“新建目标”创建，聊天没有自动识别 A/B 并派发的业务动作 |
| 船长识别任务归属，转交已有小队或新建小队 | 缺失核心闭环 | `chat.send` 保存传入的 projectId/taskId；`tick` 只产生船长文字回复，没有结构化路由、新建需求或转交记录；消息当前绑定打开的目标 |
| 不确定归属时主动反问 | 未实现可靠机制 | 没有持久化澄清状态及候选需求；自然语言回复可能问问题，但不能据此声称完成了路由确认 |
| 下级问题逐级解决，船长解决不了才找人 | 已实现主要机制 | `askParents` 先复用决定，再让 lead/captain 各最多尝试两次；仍未解决才进入人工队列；必须人工处理的高风险动作保留人工门禁 |
| 单需求队长拥有全局视角，派工与返工，对结果负责 | 部分 | 每需求独立计划、分支和工件，队长参与分工、问题处理；工序推进与返工由宿主状态机执行；队长会话目前每轮新建，靠宿主传递上下文，并非常驻记忆会话 |
| 一个工人一个或多个工序，服从小队长安排 | 部分 | 工序可编辑，按工序配置角色/运行时/模型；目前每次工序调用新会话，不支持同一个有身份连续性的工人跨工序复用 |
| 开工读工序说明，按需查询团队手册 | 部分 | 目标、输入输出、完成标准注入工人提示词；手工 CLI 有 required sources 与手册能力；桌面调度尚未接入统一团队手册检索及必读回执 |
| 积累可复用经验，沉淀并方便查询知识库 | 部分 | 手工 CLI 已有 lesson 候选、审核、检索；桌面已有决定账本，但没有把工序结束的经验提炼、审核、检索接入完整工作流 |
| 密码本保存端到端测试账号与 key | 未实现 | 当前只使用运行时自己的登录；授权与路径守卫主动拒绝秘密。没有凭据存储、按角色取用、测试进程注入及访问审计 |

## 建议实施顺序

1. **船长对话成为完整入口**：输入 → 识别已有需求/新需求/询问进度 → 必要时澄清 →
   持久化路由结果 → 转交。界面让人看见消息送到了哪个目标，并可纠正归属。
2. **接通工作手册与经验闭环**：项目选择知识来源、必读材料与按需检索；工序结束产出
   有来源的经验候选，经审核后才供其他任务复用。
3. **跨工序工人连续性**：明确何时复用已有会话、何时必须开启独立会话；独立验证员
   继续与工人隔离。
4. **受控凭据供给**：复用系统钥匙串或成熟密码管理器，持久记录只保存引用；
   凭据按任务授权注入指定测试进程，不进入聊天、工件、日志或模型提示词。

当前产品已有执行骨架，但尚未完整达到截图中的统一对话、知识积累和测试凭据体验。
这些缺口不能用安装包完成或协议测试通过来替代验收。
