# Crewvane｜协航 V0.1

交代目标，团队交付。

本版在既有 agent-ship-kit 仓库开发，命令更名为 `crewvane`，不提供旧命令别名。
桌面采用 Electron + React + TypeScript。CLI 与桌面共享 `.crewvane/events.jsonl`
中的状态和跨进程锁。源仓库地址保持不变。

## 已确认范围

- macOS arm64 内测应用；托盘后台运行，退出可恢复。
- 发现 OMP、Codex、DSH、Cursor、Qoder。前三者实现协议调度；后两者只发现。
- Herdr 是默认推荐但由用户确认安装的可选终端底座。已安装时成为终端首选，
  缺失时回退到 Shell / runtime CLI；Crewvane 的派工与通信不依赖它。
- 人 → 船长 → 每需求队长 → 临时工人；直属上级先解决，船长仍无法解决才找人。
- 按项目授权后自主开发、独立测试、发布 PR；合并、部署保持人工流程。
- 运行时与模型可按工作区、项目角色、工序、任务覆盖；仅授权范围内回退。
- 列表编辑工序，顺序阶段、阶段内并行、有限返工。功能开发与缺陷修复模板。
- 默认工人并发 3；每级问题最多尝试 2 次；独立审查最多 3 轮。
- 决定账本按项目、根因和有效期复用；只有真正升级给人的问题进入待我决定。
- 旧版卸载按归属识别；迁移先备份，不将旧合同授权转成新授权。

## 实施顺序与验收

M0：修复 #19，共享核心，CLI 更名，旧版卸载与迁移。
M1：OMP ACP、Codex App Server、DSH ACP；真实会话、模型、权限、取消、恢复。
M2：层级调度、授权、升级与决定账本；恢复和全局容量。
M3：可配置工序、独立验证、返工、集成分支、幂等 PR。
M4：项目接入、待我决定、船长对话、需求详情、运行时、工序、项目设置。
M5：打包 .app 与 DMG/ZIP 下载附件，真实多需求试用，记录证据和剩余限制；
通过 GitHub Releases 交付安装包与 SHA-256 校验，正式发布前保留草稿验收。

Issue #20 的账本、升级清单和三轮审查纳入本版；自动合并/上线档留到后续版本。
首版固定 `external-approval`，不能通过 Agent 修改策略绕过人工流程。

## 产品化原则

- 先把需求拆成桌面、UI、终端、协议、测试等边界，再优先复用成熟开源库。
- 自有价值集中在持久任务状态、层级决策、可配置工序、授权、证据和注意力管理。
- 运行时发现、连接协议、模型、终端能力分别建模，不能把“看见程序”当作“可派工”。
- Herdr 提供观察与接管体验，不是通信总线；没有它也不牺牲多 Agent 调度。
- 默认体验可以推荐组件并减少点击，但安装本机二进制仍需要用户当场确认。
